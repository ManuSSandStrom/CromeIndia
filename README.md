# Crome India

Premium sports-surfaces and sports-infrastructure website built with React, Express and MongoDB.

## Stack

- React 18, Vite, React Router, Framer Motion, Axios and modular CSS
- Node.js, Express, MongoDB and Mongoose
- JWT admin authentication, bcrypt password hashing, Helmet, CORS, validation and rate limits
- Public SEO routes with metadata, canonical URLs, JSON-LD, `robots.txt` and a database-backed `sitemap.xml`

## Local setup

1. Copy `server/.env.example` to `server/.env` and configure `MONGODB_URI`, `JWT_SECRET` and `CLIENT_URL`.
2. Copy `client/.env.example` to `client/.env` only if a non-default API URL is needed.
3. Run `npm install`, then `npm run seed-content` to add the approved Crome India product, sports, services, FAQ and company data.
4. Run `npm run dev`. The client runs at `http://localhost:5173`; the API runs at `http://localhost:4000`.

The administrator account is managed in the database. Sign in at `/admin/login` with the admin username and password configured for this installation. To create the first account, set `BOOTSTRAP_ADMIN_EMAIL` and a `BOOTSTRAP_ADMIN_PASSWORD` of at least 16 characters, then run `npm run create-admin -w server`. To reset or set the requested admin credentials, set `ADMIN_LOGIN_NAME` and `ADMIN_LOGIN_PASSWORD` for one command and run `npm run set-admin-credentials -w server`; this updates only that account and stores a bcrypt hash. Run it from a machine whose IP is allowed by the MongoDB Atlas network access list. There is no public registration endpoint.

## Public pages

- `/`, `/about`, `/contact`, `/request-quote`, `/request-call`
- `/sports` and `/sports/:slug`
- `/products` and `/products/:slug`
- `/services` and `/services/:slug`
- `/gallery`, `/find-your-surface`, `/privacy-policy`, `/terms`

The catalogue filters by configured categories, sports and recorded pile heights. Product pages show only populated specification fields. Product comparison is limited to three records. The surface finder matches only current catalogue records. The gallery starts empty and has no stock photography.

## Admin

The admin workspace provides an enquiry CRM, product/category/sport/service/FAQ editors, site settings, a media library and gallery management. Leads can be filtered, assigned, updated through the CRM statuses, annotated and exported as CSV. Uploaded JPG, PNG, WebP and AVIF images are signature-checked and limited to 8 MB; media files are stored under `server/uploads` and served from `/media`. Back up this directory or replace it with durable object storage before using ephemeral production hosting.

## API overview

- `POST /api/v1/leads` — validated public enquiry and callback submission
- `GET/PATCH /api/v1/leads` and `GET /api/v1/leads/export` — protected CRM operations
- `POST /api/v1/auth/login`, `GET /api/v1/auth/me` — administrator authentication
- `/api/v1/products`, `/categories`, `/sports`, `/services`, `/gallery`, `/faqs` — published public content and admin CRUD
- `/api/v1/admin/content/:type` — protected content listing
- `POST /api/v1/admin/media/upload` — protected image upload
- `POST /api/v1/ai/chat` — server-side assistant using published Crome India content only
- `GET/PUT /api/v1/settings`, `POST /api/v1/analytics/events`
- `GET /health`, `/robots.txt`, `/sitemap.xml`

## Build and deployment

The frontend deploys to Vercel and the API deploys to Render from this repository root. The root `vercel.json` builds the client workspace and publishes `client/dist`; `render.yaml` describes the Node web service and its health check.

### Vercel

1. Import this repository in Vercel and leave the project root directory as `.`. The checked-in configuration runs `npm ci`, builds `client`, and publishes `client/dist`.
2. Set `VITE_API_URL` to `https://<your-render-service>.onrender.com/api/v1` in the Vercel project environment variables for Production (and Preview if you deploy previews). Do not add a trailing slash.
3. Redeploy after setting the variable. Vite embeds it at build time.

### Render

1. Create a Blueprint from this repository and accept `render.yaml`, or create a Node web service with build command `npm ci`, start command `npm run start -w server`, and health check path `/health`.
2. Set `MONGODB_URI` to the production MongoDB connection string and `CLIENT_URL` to the exact deployed Vercel origin (for example `https://crome-india.vercel.app`, without a trailing slash). For multiple trusted frontend origins, separate origins with commas.
3. `JWT_SECRET` is generated by the Blueprint. Keep it private and stable between deploys. `GEMINI_API_KEY` is optional; set it only if the assistant should use Gemini.
4. Set `TRUST_PROXY=true` behind Render's reverse proxy. Create the first administrator with `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` in the Render environment, then run `npm run create-admin -w server` from a trusted local machine connected to the production database. Remove the bootstrap variables afterward.
5. Restrict MongoDB network access appropriately and configure regular backups. Uploaded files in `server/uploads` are local to the service; configure persistent storage or external object storage before relying on uploaded media in production.

### Pre-deploy checks

Run `npm ci`, `npm run build`, and `npm test` from the repository root. For local development, the Vite `/api` proxy continues to target `http://localhost:4000`; production calls the Render API directly through `VITE_API_URL`.

Only approved Crome India information belongs in the public catalogue. Do not add unsupported product specifications, certifications, pricing, offers or project claims.
